# Pilot runbook

Start on a separate branch with synthetic orders; choose one real store only after go-live gates are met. Assign a responsible operator, bank/account owner and rollback contact. No production env values, customer PII, raw signatures or capability URLs belong in reports.

1. Confirm the correct store, receiver account/holder/VA, amount and payment content in the bank app; PR5 merge is not proof of this check. Pilot demo catalog seed is optional: `ZENO_SEED_PILOT=1 SEED_STORE_ID=<uuid> npm run seed:pilot` is a dry run. Execution requires `--execute`, Neon endpoint attestation and, for production only, both `--production` and `ZENO_ALLOW_PROD_SEED=YES`. It seeds catalog only; configure tables/zones and actual owners through the normal UI. It never verifies an account or creates paid orders.
2. Test a small authorized payment through SePay HMAC from the exact raw body, with API-key mode tested separately if supported by the account. Verify invalid/tampered/stale requests write no payment, and valid delivery receives success only after the DB commit. Verify account-plan permissions and actual API v2 parameters/pagination with provider docs/account.
3. Replay a delivery concurrently: one bank record/payment/event transition; no double paid total. Keep webhook integer ID and API UUID as distinct authoritative source identities. Cross-source alias matching stays off unless reference/account/VA/amount/time uniqueness has been verified for this integration. Record actual IDs only in restricted provider evidence.
4. Check exact amount, underpayment, overpayment, missing/wrong code, wrong receiver, duplicate paid order, cancellation then transfer, expiry then late transfer, replaced QR and payment already recorded manually. Exceptions must enter the right reconciliation queue; never auto-fulfil a cancelled order merely because money arrived. Owner assignment/refund notes must remain scoped and auditable; staff/other tenants must be denied.
5. Pause delivery in a controlled rehearsal; reconcile through the API, including overlapping windows, rate limiting and retry after partial import. Verify no lost or duplicated money and no checkpoint advancement after failure. Webhook-only accounts require manual reconciliation; do not call API fallback verified for those accounts.
6. Verify Neon job cadence and a deliberately failed monitor with the actual recipient. Disable/re-enable schedules, verify stale health becomes red, then recover. Keep these tests off production unless the operator approved the interruption.
7. Exercise QR-at-table, pickup, delivery, cash and online flows on physical iOS/Android and café Wi-Fi. Compare Lighthouse/a11y reports with actual device behavior; CI WebKit is not an actual bank app/iPhone payment test.
8. Reconcile pilot order totals, bank statement and review/refund queue; freeze the record and obtain go/no-go sign-off. Stop accepting orders/disable jobs and use `operations.md` on any unexplained mismatch.
